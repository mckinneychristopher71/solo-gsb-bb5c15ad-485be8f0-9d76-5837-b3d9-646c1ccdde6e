# ⚖️ 两两决策台（Pairwise Decision Desk）

粘贴 3～12 个候选项，逐对比较并记录胜者或平局，系统按 **Schulze 最强路径法** 实时计算排名。

- 后端：FastAPI + SQLite（标准库 `sqlite3`，无额外依赖）
- 前端：原生 HTML / CSS / JavaScript（单页，无构建步骤）
- 进度持久化：评审记录存入 SQLite，浏览器刷新后自动恢复

## 🚀 启动（唯一命令）

```bash
docker compose up --build
```

该命令会自动完成：构建镜像 → 安装依赖 → 启动服务（首次启动时自动创建 SQLite 数据库与表结构）。

启动后访问：

| 项目 | 地址 |
| ---- | ---- |
| 网页 | <http://localhost:8000> |
| API 文档（Swagger） | <http://localhost:8000/docs> |

停止：`Ctrl + C`；删除持久化数据：`docker compose down -v`。

## 🖱️ 使用说明

1. **录入候选项**：每行一个，3～12 个，名称不可重复，点击「开始评审」。
2. **逐对评审**：界面依次展示每一对组合，点击左侧 / 右侧按钮选择胜者，或点「平局」。
   快捷键：`←` 左边胜、`→` 右边胜、`↓` 平局、`Ctrl+Z` 撤销。
3. **实时排名**：按 Schulze 最强路径法计算，并列的候选项归入同一名次组（以「＝」连接，黄色徽标）。
4. **尚未比较的组合**：以标签形式列出所有待比较组合。
5. **下一对推荐**：「下一对推荐」卡片自动给出当前最值得优先评审的组合，
   展示推荐理由（影响分）与「左胜 / 平局 / 右胜」三种结果各自的排名预览。
   点击「立即评审这一对」可跳转到该组合直接判定（判定接口接受任意待比较组合），
   跳转后随时可点「返回原顺序」；不跳转则完全按原顺序继续，二者互不影响。
   每次新增判断、撤销、复核或批量改判后，推荐都会自动重新计算。
6. **排名依据面板**：在实时排名中点击两个候选项的名称，或在胜负矩阵中点击
   行/列标题（也可直接点击任意普通单元格选中对应组合），下方即展开「排名依据」面板，
   展示两者之间的**双向最强路径**：每条路径的节点链、各边类型（胜负 / 平局）、
   边数与瓶颈强度，并给出最终「领先 / 落后 / 并列」判定（与实时排名一致）。
   路径不可达时明确显示「无有效路径」（双向均不可达即并列）。再次点击已选名称、
   点击第三个候选项（保留最新两个）或「✕ 关闭」可调整选择。
   每次新增判断、撤销、复核或批量改判后，面板随当前状态自动重新拉取并刷新。
7. **胜负矩阵**：行 vs 列，`✓` 行胜、`✗` 行负、`＝` 平局、`·` 未比较。
8. **循环冲突复核**：当严格胜负关系构成环（如 甲胜乙、乙胜丙、丙又胜甲）时，「循环冲突复核」
   卡片自动出现，展示最短冲突环路径；环上组合在卡片与胜负矩阵中同步以红色高亮。
   - **手动改判**：点击卡片中的组合标签或矩阵中的红色格，在展开的面板中重新选择胜者或平局：
     后端**原位替换**该组合的记录，进度总数与已完成数保持不变，排名、待比较组合与
     下一条冲突立即重算；若冲突解除，卡片自动消失。
   - **最少改判方案**：卡片同时给出后端基于当前严格胜负边计算的建议——把**最少数量**的组合
     批量改为平局即可消除全部有向环（平局与未比较组合不参与计算）。面板列出建议组合、
     每条受影响结果（原胜负 → 平局）以及应用后的排名预览；建议组合在矩阵中以黄色高亮。
     存在多个最优方案时，按**判断记录顺序**稳定选择（优先改判更早记录的组合）。
     点击「确认并批量改为平局」一次确认后批量应用；更新在单个 SQLite 事务中完成，
     判断记录 id、进度统计与撤销顺序均不变，随后自动重算排名与冲突。无冲突时不显示建议。
9. **撤销 / 重置**：「撤销上一判断」回退最近一次判断；「重置本轮」清空本轮全部判断（保留候选项）；「新一轮」重新录入候选项。
10. **停用 / 恢复候选**：评审进行中可随时在「候选管理」面板停用任一候选（**至少保留 3 个启用候选**，只剩 3 个时停用按钮自动禁用）。
    - 停用**不会删除**该候选的任何判断记录；后端立即只用启用候选重算进度、待比较组合、Schulze 排名、
      胜负矩阵、循环冲突、最少改判方案与下一对推荐；
    - 恢复后该候选按**最初录入顺序**回到评审：与其他候选已比较过的组合沿用原判断记录，
      只有此前未比较的组合重新进入待评审；
    - 停用或恢复后，若当前跳转组合、循环冲突复核选择或「排名依据」选择引用了停用候选，会被安全清空；
      撤销仍按原始判断记录顺序工作（可撤销涉及停用候选的历史判断）；
    - 停用状态持久化在 SQLite 中，刷新页面后自动恢复。
11. 刷新页面后进度自动恢复（会话 ID 存于浏览器 localStorage，数据与停用状态存于 SQLite）。
12. **情景沙盘**：点击评审台工具栏的「🧪 情景沙盘」进入沙盘，对**已判或未判**的任意组合暂存
    任意次「左胜 / 平局 / 右胜」改动。沙盘以「原判断 + 暂存覆盖层」在后端重算
    Schulze 排名、循环冲突与进度，页面并列展示**原结果**与**沙盘结果**，并逐项标注
    名次升降（▲/▼ 及原名次）。沙盘操作只写独立的覆盖层草稿，**绝不写入 judgments**；
    草稿持久化在服务器 SQLite 中，**刷新页面后自动恢复**（工具栏入口显示「N 项暂存」徽标）。
    可随时「丢弃草稿」，或「一次确认应用全部改动」：已判组合在**单个 SQLite 事务**中原位
    更新（记录 id、进度与撤销顺序不变），未判组合补写；应用前后端校验基础判断未变化，
    若期间发生过新增 / 撤销 / 复核 / 批量改判 / 重置 / 停用恢复，则**整体拒绝并保留草稿**
    （沙盘顶部红色提示），正式视图不受任何影响。

## 🧪 情景沙盘

- 入口：评审台工具栏「🧪 情景沙盘」按钮（页面与 API 端口不变，仍为 `http://localhost:8000`）。
- 暂存覆盖层保存在独立表 `sandbox_drafts`（每会话一行，含改动列表与基础判断指纹
  `base_version`），与 `judgments` 完全隔离：沙盘期间正式排名、进度、冲突与推荐接口
  的字段和行为保持不变。
- `GET /api/sessions/{id}/sandbox` 为纯只读，返回 `draft`（含每条改动的原值 `original`
  与是否生效 `effective`、是否已过期 `stale`）、`base_version`、原状态 `base_state`、
  沙盘状态 `state` 与每个候选的名次变化 `rank_moves`（`base_rank` / `sandbox_rank` /
  `delta`，正为上升）。无草稿时沙盘状态等于原状态。
- `PUT` 整体替换草稿（组合按候选录入序归一化，与基础判断相同的条目不保留，空草稿即删除）；
  `DELETE` 丢弃草稿。含停用候选的组合返回 409。
- `POST /api/sessions/{id}/sandbox/apply`：单个事务内先比对基础判断指纹，不一致即回滚
  返回 409 且草稿保留；一致则对已判组合 `UPDATE`、未判组合 `INSERT`，提交后删除草稿。

## 🧮 排名算法

Schulze 最强路径法：路径强度为路径上最弱一环，最强路径取各路径最大值。
计票约定：胜 = 1，平局 = 0.5（双向），未比较 = 0。
候选项 X 严格优于 Y 当且仅当 `p(X,Y) > p(Y,X)`，相等则并列，据此划分有序并列组。

## 📊 排名依据（双向最强路径）

选择任意两个候选项后，`GET /api/sessions/{id}/ranking-basis?a=X&b=Y` 返回：

- `verdict`：相对请求顺序 `a` / `b` 的最终判定——`"a"` = X 领先、`"b"` = Y 领先、
  `"tie"` = 并列；`strength_ab` / `strength_ba` 为双向最强路径强度；
- `path_ab` / `path_ba`：各方向重建出的最强路径，含 `nodes`（节点链）、`edges`
  （每条边的 `kind`：`win` 胜负边 / `tie` 平局边，及 `strength`）、`hops` 边数、
  `strength` 瓶颈强度；不可达时 `exists = false`、`strength = 0`，面板显示「无有效路径」。

路径在与排名**相同的 Schulze 计算**中重建，并与 Floyd–Warshall 强度矩阵逐向交叉核对：

1. 先用 Floyd–Warshall 变体求出最强瓶颈强度 S（无路径则 S = 0）；
2. 在「边强度 ≥ S」的子图上按层 BFS，**同强度路径优先边数更少者**；
3. 边数也相同时，按路径节点的候选录入序序列取字典序最小者——决胜只依赖
   候选录入顺序，结果稳定、可复现；
4. BFS 每个节点只定值一次，路径不重复节点（简单路径）。

该接口为纯只读：不写库、不影响进度，且不改变任何现有接口的字段与行为。
前端在每次新增判断、撤销、复核或批量改判返回新状态后丢弃缓存并自动重新拉取，
面板始终与当前排名一致；在途的过期响应按请求序号丢弃，不会覆盖新结果。

## 🎯 下一对优先级推荐

- 对每个**尚未比较**的组合，后端分别模拟「左胜 / 右胜 / 平局」三种结果并重算 Schulze 排名。
- **影响分**：在所有候选对 {X, Y} 中，其相对次序状态（X 前 / X 后 / 并列，取自排名分组）
  在三种模拟结果之间发生变化的候选对数量。影响分越高，该组合的结果对最终排名的决定性越强。
- 推荐**影响分最高**的组合；同分时按现有待比较顺序（候选录入顺序）取先者，保证推荐稳定可复现。
- 状态接口新增 `next_pair` 字段：`a` / `b` 推荐组合，`impact` 影响分，
  `candidate_pairs` 候选对总数（影响分上限），`previews` 三种结果各自的排名预览；
  全部比较完毕时为 `null`。新增判断、撤销、复核、批量改判后随状态自动重新推荐。
- 全部模拟在内存中完成：**不写入数据库、不改变完成进度**（进度仍只统计实际判断记录）。
- 为支持一键跳转评审，`POST /api/sessions/{id}/judgments` 现在接受**任意尚未比较**的组合
  （组合按候选录入顺序存储，`result` 相对请求中先出现的 `a` 解释）；
  已判定组合仍返回 409，原有按顺序评审的调用方式不受影响。

## 🔄 循环冲突检测与最少改判方案

- 仅以**严格胜负**判断构成有向边（胜者 → 败者）；平局与未比较的组合不成边。
- 在该有向图中寻找**最短有向环**作为冲突路径，随状态接口返回（`conflict` 字段，
  含环上候选项序列 `cycle` 与环上各组合 `edges`）；无环时为 `null`。
- 存在多个同长度环时，按候选录入顺序稳定选择（环以其最早录入的成员开头，取字典序最小者）。
- 复核修改通过 `PUT /api/sessions/{id}/judgments` 原位更新记录（行 id 与记录数不变），
  因此进度统计与撤销顺序不受影响，返回状态中已包含重算后的排名与下一条冲突。
- **最少改判方案**：把严格胜负边改为平局等价于从有向图中删边，最少改判数即严格胜负图的
  **最小反馈弧集**大小（等价于寻找「逆向边」最少的顶点排列，用子集 DP 对 n ≤ 12 精确求解）。
  状态接口的 `suggestion` 字段随冲突一同返回：
  - `pairs`：建议改判的组合，`change_count`：改动数；
  - `affected`：每条组合的受影响结果（`from` 原严格胜负 → `to` 平局）；
  - `preview_ranking`：应用后的 Schulze 排名预览。
  无冲突时 `suggestion` 为 `null`。存在多个最优方案时，严格边按**判断记录 id 顺序**编号，
  取编号集合字典序最小者，保证建议稳定、可复现。
- 批量应用通过 `POST /api/sessions/{id}/resolve-conflicts` 完成：所有 `UPDATE` 在
  **单个 SQLite 事务**中执行（任一组合与当前建议不符或已非严格胜负即整体回滚），
  只原位改判、不增删记录，因此判断记录 id、进度与撤销顺序不变；提交后重算排名与冲突。

## 🧩 候选停用与恢复

- 停用名单持久化在 `sessions.disabled`（JSON 数组，按候选录入顺序排列）；
  `sessions.candidates` 始终保留**全部候选与最初录入顺序**，停用不改动任何判断记录。
  升级旧库时启动脚本会自动为旧表补齐 `disabled` 列（默认空名单），旧数据无感兼容。
- 状态接口的 `candidates` 字段只包含**启用候选**（按最初录入顺序过滤），另有
  `disabled` 字段列出停用候选（同序）。前端所有面板（排名、矩阵、待比较、冲突、推荐）
  与后端全部计算都只使用启用候选：
  - 进度 `done/total` 与待比较组合只统计**双方均启用**的组合；涉及停用候选的记录保留在库、不计入；
  - Schulze 排名、最强路径、胜负矩阵、最短有向环、最少改判方案与下一对推荐均在启用候选子集中重算；
  - 含停用候选的新判断 / 复核 / 排名依据请求分别返回 409 / 409 / 422，恢复后即可正常使用。
- **恢复语义**：候选按最初录入顺序回到评审；其与其他启用候选之间已有判断的组合直接沿用，
  仅此前未比较的组合重新进入待评审，`current_pair` 按原顺序取第一个缺失组合。
- **撤销**：`undo` 始终删除会话中 `id` 最大的判断记录（可能涉及停用候选），记录顺序不变；
  状态中的 `can_undo` 依据**全部**判断记录，因此停用时仍显示可撤销。
- 停用或恢复成功后返回完整重算状态；前端会清空引用停用候选的跳转焦点、冲突复核选择与
  排名依据选择，避免面板指向不存在的组合。

## 📡 API 概览

| 方法 | 路径 | 说明 |
| ---- | ---- | ---- |
| POST | `/api/sessions` | 创建评审会话（body: `{"candidates": [...]}`） |
| GET | `/api/sessions/{id}` | 获取完整状态（进度、当前对、排名、矩阵、待比较组合、循环冲突、最少改判建议、下一对推荐、停用名单） |
| GET | `/api/sessions/{id}/ranking-basis?a=X&b=Y` | 「排名依据」：X/Y 双向最强路径（节点链、各边类型与强度、瓶颈强度、边数）与领先/落后/并列判定；纯只读 |
| POST | `/api/sessions/{id}/judgments` | 记录判断（body: `{"a","b","result": "a"\|"b"\|"tie"}`）；接受当前对或任意待比较组合（用于推荐跳转） |
| PUT | `/api/sessions/{id}/judgments` | 复核修改：原位替换一条已判定组合的结果（body 同上），进度不变 |
| POST | `/api/sessions/{id}/resolve-conflicts` | 一次确认批量应用最少改判方案：单事务把建议组合改为平局，重算排名与冲突 |
| POST | `/api/sessions/{id}/candidates/deactivate` | 停用候选（body: `{"name": "..."}`）：保留其全部判断记录，仅按启用候选重算；至少保留 3 个启用候选 |
| POST | `/api/sessions/{id}/candidates/reactivate` | 恢复已停用候选（body 同上）：按最初录入顺序回到评审，已有组合沿用原判断，仅缺失组合重新待评审 |
| GET | `/api/sessions/{id}/sandbox` | 情景沙盘：原状态、沙盘状态（原判断＋暂存覆盖层重算）、草稿、基础指纹与名次升降；纯只读 |
| PUT | `/api/sessions/{id}/sandbox` | 保存（整体替换）沙盘暂存草稿；只写覆盖层，不写 judgments，空草稿即删除 |
| DELETE | `/api/sessions/{id}/sandbox` | 丢弃沙盘草稿（judgments 不受影响） |
| POST | `/api/sessions/{id}/sandbox/apply` | 一次确认应用全部暂存改动：基础判断未变化才在单事务中原位更新/补写，冲突则拒绝并保留草稿 |
| POST | `/api/sessions/{id}/undo` | 撤销最近一次判断 |
| POST | `/api/sessions/{id}/reset` | 重置本轮全部判断 |
